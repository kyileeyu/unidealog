        <p>FigJam을 사용해 기존 서비스에서 각각 개발되고 있던 Axios Interceptor를 분석했습니다.<br>

        솔루션에서 사용 시, instance를 주입받고, SDK에서는 받아온 instance에 Interceptor만 추가하는 방식입니다.</p>

<div class="phase-slide">
  <h1 class="phase-title"><span class="blue">Phase 2 :</span> Monorepo 전환 및 종속성 제거</h1>

  <div class="phase-content">
    <div class="problem-section">
      <span class="label-btn yellow">문제 인식</span>
      <p>Phase 1의 Auth SDK는 Axios에 의존적인 문제점이 있어 HTTP Client(fetch,ky 등)에 토큰을 주입하기 어려운 구조였습니다. 또한 Error Dialog가 React Context에 종속 되어 있는 문제를 해결하기 위해 리팩토링을 진행했습니다.</p>
    </div>

    <div class="two-cols">
      <div class="feedback-preview">
        <div class="screenshot-placeholder small">개선 피드백 정리</div>
      </div>
      <div class="details">
        <h3 class="detail-title blue">Monorepo 구성</h3>
        <p>React 의존성을 제거하기 위해 pnpm의 workspace 기능을 사용해 모노레포를 구성했습니다.<br>
        <strong>core</strong>와 <strong>react</strong> 패키지로 나누었으며, 사용자의 입장에서는 react를 사용하지 않는다면 core 라이브러리만 불러와서 token을 사용할 수 있도록 설계했습니다. react에서는 core의 기능을 re-export하여 하나의 라이브러리만 불러와도 전체를 사용할 수 있게 만들었습니다.</p>

        <h3 class="detail-title blue">fetch 기반 에러핸들러 설계</h3>
        <p>core의 내부는 fetch를 사용하여 Axios의존성을 제거하였고, class 구조로 token을 관리하였습니다.<br>
        react 패키지와는 EventEmitter로 통신하며, core 패키지에서 emit한 에러코드에 따라 react 패키지에서 적절한 dialog를 보여줍니다.</p>

        <h3 class="detail-title blue">Changesets 릴리즈 관리</h3>
        <p>기존 Auth SDK에서 점진적 전환을 위해 pre-release 버전을 관리해 각 개발팀의 피드백을 받아 개선했습니다. 스크립트로 자동 배포가 가능하도록 Changesets를 설정했습니다.</p>
